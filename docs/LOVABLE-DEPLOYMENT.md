# تكامل Lovable: الواجهة على Lovable والخادم داخل حاوية منفصلة

## القرار المعماري

هذا المشروع React/Vite في الواجهة، لكنه يحتاج API يعمل كخدمة Node مستمرة ومتصفح Playwright حقيقياً. لذلك يستخدم Lovable لبناء واستضافة الواجهة فقط، بينما يعمل `server/main.mjs` و`server/browser-worker.mjs` معاً داخل خدمة حاويات مستقلة. يبقى عامل المتصفح خاصاً على loopback داخل الحاوية ولا يُنشر كواجهة عامة.

هذا المسار يحافظ على رحلة المستخدم المطلوبة: المحادثة تنتج المسودة، والخادم يفتح جلسة المتصفح المعزولة ويتيح للمستخدم مراجعة/إدخال المسودة، ثم يتوقف قبل ضغط النشر. لا ينقل Playwright إلى Edge Functions ولا يستبدله بواجهة كشط. لا يتطلب المسار Supabase أو ربطاً مع MAAROOF AI.

## نشر الواجهة في Lovable

1. استورد المستودع `ahmedfouaadqi-glitch/MAAROOF-Editorial-Agent` إلى Lovable عبر ربط GitHub، أو افتح المشروع الموجود المرتبط بالمستودع.
2. اجعل أمر البناء `npm run build` ومجلد المخرجات `dist`. المشروع يستخدم Vite وReact، ويتطلب Node.js 22 أو أحدث كما يحدد `package.json`.
3. في متغيرات بيئة **الواجهة** على Lovable، اضبط `VITE_API_BASE_URL` على أصل API العام باستخدام HTTPS، مثل `https://editorial-api.example.com`، بلا مسار `/api` ولا slash أخير. هذا العنوان ليس سراً؛ سيُضمّن في JavaScript العام عند البناء.
4. أعد بناء الواجهة بعد تغيير المتغير. لا تضف `ADMIN_API_TOKEN` أو `BROWSER_AGENT_TOKEN` أو مفاتيح النموذج/Firecrawl إلى أي متغير يبدأ بـ `VITE_`.
5. يمكن إضافة دومين مخصص للواجهة؛ أدرج أصل كل دومين مسموح به في `CORS_ORIGIN` على الخادم كما هو تماماً، بما في ذلك `https://` والمنفذ إن وجد.

إذا لم يُضبط `VITE_API_BASE_URL` في بناء إنتاجي، لن تستخدم الواجهة عنوان localhost المحلي، وستعرض تنبيهاً يطلب ضبطه.

## نشر الخادم والعامل داخل حاوية

استخدم خدمة تدعم Docker/حاويات طويلة التشغيل، مثل Railway أو Render أو خادمك الخاص. ابنِ الصورة من جذر المستودع باستخدام `Dockerfile.backend`، ثم شغّل نسخة واحدة فقط من الحاوية. الصورة تتضمن Chromium وPlaywright، وتشغّل API والعامل معاً؛ العامل يبقى على `127.0.0.1:8788`، بينما يستقبل API الحركة العامة عبر TLS proxy/المنصة على المنفذ الذي توفره المنصة.

عامل المتصفح يشغّل تلقائياً وسيط CONNECT على `127.0.0.1` بمنفذ محلي عشوائي غير مكشوف. كل نفق يسمح بـHTTPS على المنفذ 443 فقط؛ يحل الوسيط DNS مرة واحدة، ويرفض أي جواب خاص/محجوز، ثم يفتح socket إلى عنوان IP العام المحدد بدلاً من إعادة حل اسم المضيف عند الاتصال. يستخدم Chromium هذا الوسيط ويعطل QUIC وUDP WebRTC غير الممرر. لا تضف منفذ الوسيط إلى إعدادات النشر ولا تنشره للعامة.

أضف قرصاً دائماً واربطه إلى `/app/data`. ملف JSON والوسائط محلية وتدعم عملية واحدة فقط؛ لا تشغّل نسخاً متعددة ولا autoscaling لهذه الصورة. حفظ القرص يمنع ضياع البيانات عند إعادة بناء الحاوية، لكنه لا يحول JSON إلى قاعدة بيانات معاملات. جلسات المتصفح نفسها مؤقتة وقد تحتاج تسجيل دخول جديداً بعد إعادة تشغيل العامل.

### متغيرات الخادم

- `HOST=0.0.0.0` و`API_ALLOW_REMOTE=true` كي يستقبل API طلبات المنصة. لا تفتح منفذ العامل للعامة.
- `PORT` يضبطه موفر الحاويات عادةً؛ وإلا يستخدم API المنفذ `8787`.
- `ADMIN_API_TOKEN`: سر عشوائي قوي بطول 32 محرفاً على الأقل. لا تضعه في إعدادات Lovable أو متغيرات الواجهة.
- `BROWSER_AGENT_TOKEN`: سر مستقل بطول 32 محرفاً على الأقل، وتُستخدم القيمة نفسها لـAPI والعامل.
- `BROWSER_AGENT_HOST=127.0.0.1` و`BROWSER_AGENT_ALLOW_REMOTE=false` و`BROWSER_AGENT_URL=http://127.0.0.1:8788`.
- `DATA_FILE=/app/data/editorial-agent.json` و`MEDIA_DIR=/app/data/media`.
- `CORS_ORIGIN`: قائمة أصول مفصولة بفواصل، كل أصل مطابق حرفياً لواجهة موثوقة، مثلاً `https://my-editor.lovable.app,https://editor.example.com`. يمكن إضافة أصل Preview مضبوط بدقة إذا كان عنوانه ثابتاً. لا تستخدم `*` أو نمط wildcard.
- مفاتيح النموذج وFirecrawl اختيارية، وتبقى في إعدادات الخادم فقط.

تحقق من `GET https://editorial-api.example.com/health` قبل ضبط الواجهة. هذا المسار عام ويعرض حالة الخدمة والتكاملات، أما بقية API فتحتاج رمز الإدارة.

## حد الاستخدام الحالي

هذه تهيئة خاصة لمستخدم إداري واحد وليست تحويل المنتج إلى SaaS متعدد المستخدمين. API الحالي يستخدم رمزاً إدارياً مشتركاً، و`workspaceId` ليس حد صلاحيات بين مستخدمين؛ لذلك احمِ عنوان API نفسه ببوابة Zero Trust أو allowlist موثوق، ولا تعتبر CORS أو رمز التطبيق وحدهما بديلاً عن حاجز الشبكة. ملف JSON مناسب لنسخة واحدة على قرص دائم فقط. وسيط CONNECT يثبت IP لمسار HTTPS ويعالج نافذة DNS rebinding بين الفحص والاتصال في مسار Chromium، لكن يلزم أيضاً حظر خروج شبكي مباشر من الحاوية (خصوصاً UDP/مسارات غير HTTP) ومراجعة أمنية مستقلة قبل أي عرض عام. هذه الإجراءات الشبكية تُضبط لدى مزود الاستضافة ولا يمكن تفعيلها من ملف Lovable أو المستودع وحده.
