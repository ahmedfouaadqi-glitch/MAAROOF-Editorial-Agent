# MAAROOF Editorial Agent

وكيل تحرير مستقل بواجهة محادثة ثنائية اللغة (العربية/الإنجليزية)، وسجل محادثات محلي، ومنتقي منصات ومجلات. لا يتصل هذا المشروع بـ MAAROOF AI ولا يستخدم Supabase.

## ما يعمل حالياً

- الواجهة الأساسية محادثة موجّهة بالمهام مع History، أمثلة قابلة للتعبئة، RTL/LTR، وهوية بصرية بالأصفر والأسود؛ صفحات لوحة العمل القديمة باقية كأدوات ثانوية.
- مساحات عمل قابلة للإنشاء والتبديل من `+`؛ لكل محادثة ومكتبة ومقال وهوية/تكرار نطاق مساحة مسجل. التخزين يبقى JSON محلياً واشتراك المساحات لا يحل محل مصادقة المستخدمين.
- يعرض مسار التنفيذ ملخص الطلب والخطوات المنفذة والمتخطاة، ويدعم الإيقاف التعاوني وإعادة المحاولة والمتابعة.
- تحفظ المسودات المنتجة تلقائياً في مكتبة مساحة العمل، مع معاينة وتنزيل Markdown والعودة إلى المحادثة المرتبطة. المسودات المحفوظة ليست منشورات منشورة.
- شاشة البدء تعرض أمثلة مهام تحريرية قابلة للتعبئة (مقال، منشور LinkedIn، سيناريو فيديو، ونشرة)، وتحدد الوجهة وتملأ الطلب دون إرساله تلقائياً.
- منتقي موحد لـ25 وجهة (11 قناة اجتماعية/نقاشية و14 جهة مقالات/نشرات/كتابة تقنية طويلة)، يعرض الهدف والنطاق والأسلوب والصيغ باللغتين. الكتالوج قابل للإضافة ولا يدّعي أنه كل منصة اجتماعية موجودة.
- سياق اختياري للعميل والعلامة التجارية مرتبط بالمحادثة، ودليل علامة محفوظ في نطاق المساحة (الصوت، الجمهور، الحقائق/الرسائل المعتمدة وما يجب تجنبه)، مع فحص تشابه محلي ضمن نطاق الهوية. الدليل لا يثبت صحة الحقائق.
- رفع وربط صور JPEG/PNG/WebP، فيديو MP4/WebM، وملفات PDF/DOCX/TXT بالمحادثة. استخراج النص من المستندات محلي، وإرسال الصور/إطارات الفيديو لمزود النموذج فقط عند إعداد المزود. لا يُفرّغ صوت الفيديو.
- مشغل خلفي يحفظ مراحل التنفيذ ويعرض عشر خطوات في المحادثة. لا يدّعي إتمام البحث أو الكشط: مراحل Firecrawl Alexandria/استرجاع الصفحات/فحص الأدلة تُعلّم «لم تُنفذ» حتى يُجهز تكامل الاكتشاف المقيّد بالتكلفة.
- صياغة عربية أو إنجليزية بحسب لغة المحادثة، وموجز GEO يتضمن نية البحث وعبارة رئيسية وعبارات داعمة وأسئلة وكيانات؛ لا بيانات حجم بحث ولا ادعاء تحقق أو ترتيب.
- Originality Engine يفحص التطابق الحرفي والتداخل اللفظي مع المقالات والمنشورات والمسودات المحفوظة ضمن مساحة العمل ونطاق العميل/العلامة، ويعرض نوع المطابقة ونطاق المقارنة ويطلب مراجعة بشرية عند وجود إشارة تشابه أو قِصر النص. لا يدّعي كشف إعادة الصياغة دلالياً أو التشابه بين اللغات أو فحص الويب العام، ولا يصدر حكماً بالانتحال أو شهادة أصالة.
- تقرير Editorial Intelligence لكل مسودة: مؤشرات بنية النص وقابليته للقراءة وتغطية العبارات والكيانات والأسئلة، مع وصف Meta مقترح. فحص إرشادي حتمي لا يمثل ترتيباً أو تحققاً من الحقائق أو قياس ظهور GEO.
- تخزين JSON محلي وملفات محلية ضمن نموذج أولي أحادي العملية؛ هذا ليس تخزيناً إنتاجياً متعدد المستخدمين.

## تكامل Lovable

الواجهة React/Vite مناسبة للبناء والاستضافة على Lovable، لكن API وPlaywright يحتاجان خدمة Node داخل حاوية منفصلة. يتضمن المشروع `Dockerfile.backend` لتشغيل API وعامل المتصفح معاً؛ يضبط Lovable متغير الواجهة العام `VITE_API_BASE_URL`، ويضبط الخادم قائمة أصول CORS المسموح بها بدقة. لا تضع أسرار الخادم في متغيرات `VITE_*`. هذا المسار لا يستخدم Supabase ولا يربط MAAROOF AI. راجع [دليل النشر مع Lovable](docs/LOVABLE-DEPLOYMENT.md) للإعدادات والقيود.

## مزود النموذج المستقل

تُحفظ مفاتيح المزود على الخادم فقط. عند ضبط `MODEL_API_BASE_URL` و`MODEL_API_KEY` و`MODEL_NAME`، يمكن للمحادثة إرسال الطلب وسياق المرفقات المختار إلى المزود المتوافق مع OpenAI. إذا لم تُضبط القيم، تُحفظ المحادثة ويظهر تنبيه واضح بأن التوليد غير متاح. لا تُضمّن المفاتيح في Vite أو في المتصفح، ولا يوجد تكامل MAAROOF AI.

## مكتبة المهارات الموجهة

- يحتوي `skills/catalog.json` على 70 تعريف مهارة من الملف الموحّد المرفق (69 معرفاً، مع إبقاء نسختي Humanizer منفصلتين)، ولكل تعريف تعليمات المصدر في `skills/library/`. تحفظ `skills/source/` نسخة المصدر الأصلية، وتستخدم البطاقات الإنجليزية الوصف الأصلي من الأرشيف المطابق عند توفره.
- يختار الخادم تلقائياً مهارة أساسية وإرشاداً مسانداً واحداً كحد أقصى بحسب نية الرسالة ومحفزاتها والوجهة واللغة؛ يظهر الاختيار وسبب التفعيل وحالة الإتاحة ضمن المحادثة. تُحمّل تعليمات المهارات المختارة فقط بحد إجمالي 12,000 محرف.
- صياغة مقال/منشور صريح تُكيّف مع الوجهة وتعرض GEO؛ أما PRD والخطط والتقارير فتُعاد كوثائق منظمة ولا تُعامل كمسودات للنشر ولا يظهر لها browser handoff. متابعة تنقيح مسودة منشورية تحتفظ بسياق الوجهة وبوابة التسليم، إلا إذا صرّح الطلب الجديد بأنها غير مخصصة للنشر.
- تصنيف المصدر: 16 قابلة لاستخدام إرشاد صياغة عبر النموذج بعد تهيئة المزود، و43 إرشادية فقط، و11 تحتاج تكاملاً غير متاح. لا تُعد السكريبتات والموصلات والأدوات الداخلية في Manus متاحة للتطبيق لمجرد وجود نص المهارة؛ لا يمكن للتطبيق قراءة مهارات حساب Manus غير المرفقة أو تثبيتها.
- نصوص المصدر ومدخلات المستخدم تعامل كبيانات غير موثوقة. لا يتيح الموجّه استدعاء أدوات أو ملفات أو مفاتيح خارج القدرات المتاحة، ولا يوحي بإنجاز البحث أو توليد الوسائط عند غياب التكامل.

## ما لم يكتمل

- تكامل Firecrawl Alexandria داخل المحادثة: يجب أن يكتشف القدرة والسعر أولاً، ولا يستدعي أي قدرة مدفوعة قبل عرض التكلفة. خطوات البحث والكشط الحالية لا تعمل في مسار الدردشة.
- تسليم أولي من بطاقة المسودة إلى درج المتصفح المعزول داخل إطار التطبيق: يسجل المستخدم الدخول، ينقر حقل العنوان/النص في المعاينة ثم يدرج النص من المسودة. يلزم تسجيل وجهة مرة واحدة؛ لا يوجد حتى الآن توجيه تلقائي من المنصة إلى الموقع أو اكتشاف آلي موثوق للحقول، ولا تُضغط أزرار الحفظ/النشر.
- تحرير المسودة داخل الدردشة وإعادة تشغيل مراحل المراجعة، وإضافة الوسائط إلى محررات المواقع، ومعالجة أخطاء DOM الخاصة بكل منصة. لا يحدث نشر آلي ولا نقرة آلية على «نشر».
- تخزين دائم قابل للتوسع، صلاحيات وعزل مستخدمين حقيقيان، طابور مهام مستدام، تخزين كائنات إنتاجي، فحص برمجيات ضارة، نسخ احتياطية وسجلات تدقيق.
- التشابه الدلالي وإعادة الصياغة وعبر اللغات باستخدام embeddings متعددة اللغات بعد تقييمها، وفحص قواعد البيانات الخارجية/الويب العام. محرك الأصالة الحالي محلي ولفظي فقط.

## تشغيل محلي

يتطلب Node.js 22 أو أحدث.

1. انسخ `.env.example` إلى `.env`.
2. أنشئ سراً عشوائياً مستقلاً بواسطة `openssl rand -hex 32` وضعه في `ADMIN_API_TOKEN`. بعد تشغيل الخادم، أدخل القيمة نفسها في الإعدادات؛ تحفظها الواجهة في ذاكرة تبويب المتصفح الحالي فقط، لذلك ستُطلب مجدداً بعد إعادة تحميل الصفحة.
3. عيّن `MODEL_API_BASE_URL` و`MODEL_API_KEY` و`MODEL_NAME` إذا أردت تفعيل الصياغة عبر مزودك المستقل؛ لا تضع السر في متغيرات `VITE_*`.
4. لميزة المتصفح، عيّن `BROWSER_AGENT_TOKEN` إلى سر عشوائي بطول 32 محرفاً أو أكثر؛ يستخدمه API والـworker نفسه.
5. شغّل `npm install` ثم `npm run server`.
6. في طرفية ثانية شغّل `npm run dev`.
7. للـbrowser handoff، ثبّت Chromium مرة واحدة بـ`npm run browser:install`، ثم شغّل `npm run browser:worker` في طرفية ثالثة.
8. تحقّق بواسطة `npm run typecheck` و`npm test` و`npm run build`.

يعمل API افتراضياً على `http://127.0.0.1:8787` والواجهة على `http://localhost:5173`. البيانات في `./data/editorial-agent.json` والملفات في `./data/media`، وكلاهما محلي. لا تشغّل أكثر من نسخة API على ملف البيانات نفسه.

## شاشة رمز الوصول والأمان التشغيلي

- رسالة «أدخل رمز الوصول من الإعدادات» ليست خطوة تسجيل دخول لمنصة نشر؛ هي بوابة وصول إلى API المحلي. تظهر إذا لم يُدخل الرمز بعد، أو إذا لم يكن `ADMIN_API_TOKEN` مضبوطاً في `.env`، أو إذا كان الرمز لا يطابق الخادم. تميّز الواجهة الآن بين الخادم غير المهيأ، الرمز الخطأ، والخادم غير المتاح. اضغط «فتح الإعدادات»، واضبط السر في `.env` ثم أعد تشغيل API، وأدخل السر نفسه في حقل الإعدادات. لا تستخدم `BROWSER_AGENT_TOKEN` هنا؛ لهدف عامل المتصفح فقط.
- إطار المنتج ثابت RTL في اللغتين؛ تبقى عناصر التنقل على الجهة اليمنى. يتبع نص الرسائل والمسودات `dir=auto`/لغة الرسالة كي يظهر الإنجليزي LTR والعربي RTL داخل الإطار نفسه.
- توجد حالياً قيمة API واحدة بصلاحية إدارية مشتركة، ولا توجد حسابات أو عضوية مستخدمين أو صلاحيات عزل حقيقية؛ `workspaceId` نطاق سجلات وليس حدّاً أمنياً بين حسابات. أبقِ API على loopback افتراضياً. الربط البعيد يتطلب `API_ALLOW_REMOTE=true` وسراً قوياً وبوابة TLS موثوقة وجداراً شبكياً، لكنه لا يضيف مصادقة مستخدمين. لا تعرضه للعامة أو لمستخدمين متعددين قبل مصادقة مستقلة وتفويض عضوية لكل مساحة.
- يطبق API حدّاً ذاكراتياً لكل عنوان اتصال قدره 240 قراءة و60 كتابة بالدقيقة (و600 طلب preflight)، ويطبق العامل الحدود نفسها للقراءة/الكتابة مع سقف 4 جلسات متصفح متزامنة. هذه حدود أولية تُصفّر مع إعادة التشغيل وليست بديلاً عن quota دائمة خلف proxy موثوق.
- حدود الملفات: صورة حتى 10 MiB، فيديو حتى 50 MiB، PDF/DOCX حتى 15 MiB، TXT/MD حتى 2 MiB، وحصة إجمالية مشتركة 250 MiB لملفات المقالات والمحادثات. يرفض DOCX المشفر أو المسارات غير الآمنة أو أكثر من 256 عنصراً أو أكثر من 50 MiB بعد فك الضغط.
- لا يستخدم عرض React الحالي `dangerouslySetInnerHTML` أو `innerHTML` في مسارات الواجهة المفحوصة؛ النص يعرض كنص لا HTML. لا يزال فحص البرمجيات الضارة وعزل parsers في عملية/حاوية منفصلة غير منفذين. في متصفح Playwright توجد نافذة DNS rebinding متوسطة بين فحص DNS والاتصال الفعلي؛ يلزم egress proxy يثبت IP عند الاتصال أو حماية خروج شبكي مكافئة. لا نصف SSRF بأنها مغلقة.

## البحث والمتصفح

- إعداد Firecrawl/Brave الحالي يخص مسارات البحث والمقالة الأقدم، ولا يستدعيه مشغل المحادثة. التكامل مع Alexandria ما زال بنداً مفتوحاً.
- يستخدم browser handoff جلسة Playwright معزولة داخل العامل؛ لا يستعير تسجيل الدخول من Chrome الشخصي، ولا يخزن كلمات المرور أو يتجاوز CAPTCHA/MFA. الجلسات محفوظة بذاكرة العامل وتنتهي عند إغلاقها أو انتهائها. العامل يرتبط بـloopback افتراضياً؛ أي bind بعيد يتطلب `BROWSER_AGENT_ALLOW_REMOTE=true` وبوابة TLS موثوقة وجداراً شبكياً.
- لا يُبلغ عن نشر ناجح دون تحقق مستقل من الموقع الوجهة. لا تُفعّل وجهة للنشر دون مراجعة سياستها وصلاحية الحساب.
